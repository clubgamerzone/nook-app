# Build and publish Nook for Google Play internal testing

Last verified: September 2, 2026

This runbook creates Nook's first correctly signed Android App Bundle (`.aab`) from the Visual Studio Code PowerShell terminal and publishes it to Google Play's Internal testing track.

The package name is `com.clubgamerzone.nook`. Google permanently associates the package with the Play Console app after the first artifact upload.

## Important key distinction

- **Upload key:** the private key kept by the developer and used to sign every `.aab` uploaded to Play.
- **App signing key:** the long-term distribution key managed by Google Play App Signing and used to sign APKs delivered to users.
- **Debug key:** suitable only for local testing. Never use `android/app/debug.keystore` as the Play upload or app-signing key.

Back up the upload keystore and its passwords in two secure places. Do not commit them, email them, or put them in ordinary cloud storage. If the upload key is lost, Play has a reset process, but losing access still delays releases.

## 1. Open the correct VS Code terminal

Open the Nook folder in Visual Studio Code, then choose **Terminal → New Terminal**. Confirm that the shell is PowerShell and run:

```powershell
Set-Location "D:\React Native\Secret app\Nook"
git status --short
java -version
```

Use JDK 17 for this project. Do not continue if Git shows unexpected source changes.

## 2. Create the private upload keystore once

Run these commands from the project root:

```powershell
$nookSigningDir = Join-Path $env:USERPROFILE ".nook-signing"
New-Item -ItemType Directory -Force -Path $nookSigningDir
$nookKeystore = Join-Path $nookSigningDir "nook-upload.keystore"
keytool -genkeypair -v -storetype PKCS12 -keystore $nookKeystore -alias nook-upload -keyalg RSA -keysize 4096 -validity 10000
```

`keytool` asks for a new keystore password and certificate identity. Use a strong unique password generated by a password manager. Suggested identity values:

- First and last name: the verified developer or company name shown in Play Console
- Organizational unit: Mobile
- Organization: the verified developer/company name
- City, state, and two-letter country code: the developer's real legal location

Do not paste the password into chat, source code, Git, screenshots, or documentation.

Verify that the key exists:

```powershell
keytool -list -v -keystore $nookKeystore -alias nook-upload
```

Record the SHA-256 certificate fingerprint in the password-manager entry for this key.

## 3. Configure Gradle locally

In VS Code, copy:

```text
android/keystore.properties.example
```

to:

```text
android/keystore.properties
```

Edit the new file with the real path, alias, and passwords. On Windows, use forward slashes in `storeFile`, for example:

```properties
storeFile=C:/Users/jay/.nook-signing/nook-upload.keystore
storePassword=YOUR_REAL_KEYSTORE_PASSWORD
keyAlias=nook-upload
keyPassword=YOUR_REAL_KEY_PASSWORD
```

The real file is ignored by Git. Confirm before building:

```powershell
git check-ignore -v android/keystore.properties
git status --short
```

The first command must report an ignore rule, and the real properties file must not appear in `git status`.

As an alternative for CI later, Gradle also accepts these environment variables:

- `NOOK_UPLOAD_STORE_FILE`
- `NOOK_UPLOAD_STORE_PASSWORD`
- `NOOK_UPLOAD_KEY_ALIAS`
- `NOOK_UPLOAD_KEY_PASSWORD`

## 4. Build the first AAB

From the project root:

```powershell
Set-Location android
.\gradlew.bat clean bundleRelease
Set-Location ..
```

The build must finish with `BUILD SUCCESSFUL`. The bundle is created at:

```text
android/app/build/outputs/bundle/release/app-release.aab
```

Confirm it and calculate a checksum:

```powershell
$nookAab = Resolve-Path "android/app/build/outputs/bundle/release/app-release.aab"
Get-Item $nookAab | Select-Object FullName, Length, LastWriteTime
Get-FileHash $nookAab -Algorithm SHA256
jarsigner -verify -verbose -certs $nookAab
```

The bundle should verify successfully. Keep the SHA-256 value with the release record.

## 5. Upload it to Internal testing

1. Open Google Play Console and select **Nook**.
2. Go to **Test and release → Testing → Internal testing**.
3. Open **Testers**, create an email list, and add the Google-account email addresses that will test Nook. Internal testing supports up to 100 testers.
4. Return to the Internal testing release page and select **Create new release**.
5. Accept/enable **Play App Signing**. For this project, let Google generate and protect the app signing key; the locally created key remains the upload key.
6. Upload `android/app/build/outputs/bundle/release/app-release.aab`.
7. Release name: `1.0-internal-1`.
8. Use these release notes:

```text
Initial internal testing release.

Includes local organizer features, reminders, account and profile setup, invitation-based contacts, PIN-protected conversation access, realtime text chat, message retention controls, and contact safety controls.

This is a development beta. Messaging is not yet end-to-end encrypted and should not be used for sensitive information.
```

9. Save, review the warnings, and select **Start rollout to Internal testing**.
10. On the Testers tab, copy the opt-in link and send it to the approved testers. They must open it while signed into one of the listed Google accounts.

Internal releases normally become available within minutes. First-time temporary listing information can take longer to settle.

## 6. Record Play certificates for Firebase

After the first upload, open **Test and release → Setup → App integrity**. Under Play App Signing, copy both SHA-1 and SHA-256 fingerprints for:

- App signing key certificate
- Upload key certificate

Add the app-signing certificate fingerprints to the Android app in Firebase Console if Nook later uses Google Sign-In, phone authentication, App Check with Play Integrity, Dynamic Links alternatives, or APIs that validate the installed certificate. Email/password authentication does not require those fingerprints today, but preserving them in the operations record prevents future confusion.

Never commit certificate private keys. Certificate fingerprints are public identifiers and may be documented.

## 7. Every later upload

Google Play rejects a reused version code. Before every new `.aab`, increment `versionCode` in `android/app/build.gradle`. Update `versionName` when the user-facing version changes.

Example progression:

```groovy
versionCode 2
versionName "1.0.1"
```

Commit source changes first, build from that known commit, record the checksum, then upload.

## 2026 package-ownership warning

Nook APKs using `com.clubgamerzone.nook` were installed directly before the Play release. New Android developer-verification flows may ask for proof that the developer controls a previously used package name. If Play Console displays a package conflict, ownership, or `adi-registration.properties` request, stop and preserve the exact message before proceeding.

The earlier shareable APK was signed with the repository's debug certificate. That public debug key must not become Nook's permanent Play signing identity. Resolve any ownership prompt through the Play App Signing flow with the private upload key and Play's instructions.
